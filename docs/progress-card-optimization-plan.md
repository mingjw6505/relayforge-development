# 对话内进度卡片优化方案

## 目标与验收

让用户能迅速看懂“正在做什么、发生了什么变化、是否需要我操作、验证到什么程度”，并能回看阶段过程。先完成方案，再实现、验证，最后提供可切换状态的模拟预览，由用户确认视觉与交互效果。

本轮覆盖 `progress_panel` 的数据契约、状态展示、阶段历史、刷新机制、相关文档和模拟预览。保留现有灰阶、系统字体和紧凑卡片风格；保留任务隔离、revision 并发校验、终态不可改写、真实 Skill 加载凭据、验证结论独立申报等约束。不改后台 Hook 日志，不增加运行时依赖。用户已授权提交、推送任务分支，并在拉取最新 main 后合入、提交和推送 main；不创建额外发布。

## 完整设计

### 1. 首屏以当前工作为中心

- 展示任务名称、真实状态、当前阶段／最终结果、最近进展、验证状态和下一步。
- 完成后展示“结果”和“剩余：无（本次范围）”；取消后展示取消状态，不继续显示正在进行的动作。受阻时展示受阻步骤／原因。
- 未申报的“最近进展”按需隐藏；验证未申报仍明确显示“未执行”，不推断通过。
- 工作流和 Skill 移到可展开的执行记录；首屏只在有真实凭据时显示紧凑数量入口，避免空字段占位或加载列表拉长首屏。
- 展开区包含工作步骤、阶段更新、验证依据、工作流和加载凭据。阶段更新默认最近 6 条，可展开当前保留的全部记录。
- 保留键盘操作、可见焦点、语义化状态提示；支持明暗主题和 320px 窄屏。

### 2. 等待和受阻有明确语义

- `details` 增加可选 `waiting_for: user | external` 和 `reason`（最多 120 字，单行）。不指定等待对象时显示“等待中”，不推断用户必须行动。
- 等待用户时显示“等待你确认”；等待外部结果时显示“等待外部结果”。原因和下一步在首屏可见。
- 非等待／受阻状态清除失效的等待原因；完成、取消时清除旧 current/remaining。验证数据保留，除非 Agent 显式替换详情。
- 旧快照无新增字段仍可读；渲染层对旧的完成态残留也做保护。不会自动把完成等同于验证通过。

### 3. 阶段历史可回看

- 新增历史条目保存本次状态、摘要、规范化后的短详情和当前步骤（如有），不保存原始命令、输出或提示词。
- 记录列表优先展示摘要；没有摘要时从变更、当前动作、受阻原因和步骤中选取具体内容，不再统一降级为“阶段更新”。展开单条可看当时的简短验证结论和依据。
- 保留现有最多 20 条历史、7 天／200 个任务的限制；明确提示“保留最近 N 条”，不声称是无限日志。旧历史不补造不存在的详情。
- Skill 加载事件继续独立标注；加载不等于执行成功。

### 4. 刷新稳定且安静

- 同一 run_id、同一 revision 的读取只更新同步状态，不重建内容 DOM；仅新 revision 触发内容渲染。
- 保留 2 秒前台轮询、错误指数退避和过期请求隔离；页面不可见时暂停读取，恢复可见时立即同步。
- 区分“阶段最近申报时间”和“连接／同步状态”。90 秒无新阶段仅在运行且连接正常时提供中性说明，不将长检查或等待推断为卡死。
- `unknown_run` 等永久错误停止轮询并显示记录不可用；存储临时失败仍重试。暂停、恢复、终态与新任务绑定保持一致。

### 5. 模拟预览复用实际实现

- 提取可复用的卡片渲染与连接状态展示；生产入口保留 MCP 通信，预览入口只提供本地模拟数据。
- 预览复用正式卡片的模板、样式、view 和 DOM 渲染，不单独绘制一份近似图。
- 可切换进行中、验证中、等待用户、等待外部结果、完成、受阻、取消、连接中断和记录不可用；可展开历史，查看旧快照及完成后部分验证的效果。
- 模拟数据明确标注，不连接真实任务、不提交工具更新、不伪造真实验证结果；不自动改动当前聊天已安装插件。

## 数据与兼容决策

- 保持快照 `schema_version=1`，仅添加可选字段；数据库无需迁移。现有输入严格白名单继续生效。
- `details` 仍是整体替换；省略时保留有效旧详情，但状态转换时清理不再适用的字段。同步更新工具 schema、契约与文档。
- 历史新增详情是接收时的申报快照，不推导历史时间、未记录的检查或宿主活动。
- 不引入百分比、ETA、任务执行审计或后端自动测试能力。

## 验证计划

1. 前端：`npm --prefix progress_panel/web test`，补齐各状态、历史与轮询回归。
2. 服务端：`python -m pytest progress_panel/tests`；使用临时隔离开发环境解决当前缺少 pytest 的问题，不增加插件运行时依赖。
3. 构建：`npm --prefix progress_panel/web run build`，生成正式打包页面并核对无外部运行时资源。
4. 类型检查：可用时运行仓库现有 strict mypy 检查；JSON 三份清单校验，Markdown 结构及 `git diff --check`。
5. 可视与交互：用实际共享渲染器检查明暗主题、桌面／320px、阶段切换、展开记录、等待和完成状态；明确模拟预览与正式宿主验收的边界。

## 风险与交付边界

- 当前聊天运行的是已安装插件，源码修改不会自动替换当前工具及卡片；本轮通过共享渲染器的模拟预览确认效果，正式安装后的宿主兼容性需另行验证。
- 历史仍有界，只保留已有上限，不恢复之前未存储的动作或验证详情。
- 用户确认对象是已实现的展示与交互；若提出调整，基于本方案和当前代码继续迭代。
